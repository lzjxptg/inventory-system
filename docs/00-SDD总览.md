# 进销存系统 SDD 总览（Trae 执行版）

> 版本：v0.2  
> 适用阶段：基础档案 + 采购 + 销售 + 库存流水  
> 模型使用规则：每次只引用本节相关片段，禁止凭训练记忆擅自改业务规则。

## 1. 项目快照

- **项目**：中小商户进销存管理系统
- **角色**：管理员、采购员、销售员、仓库员（本期先实现权限字段，页面按角色隐藏）
- **技术栈**：FastAPI + SQLAlchemy 2.x + MySQL 8.0 + Vue 3
- **本期不含**：采购退货、销售退货、财务对账报表、多门店调拨（如要做标 `[待确认]`）

## 2. 硬规则（模型改代码必须服从）

1. 所有写操作业务接口必须走数据库事务。
2. 库存变更必须走「库存表行锁 + 流水记录」，不允许直接改库存不写流水。
3. 逻辑删除统一用 `is_deleted=0/1`，查询默认过滤 `is_deleted=0`。
4. 金额字段 `DECIMAL(12,2)`，数量 `DECIMAL(12,3)`，禁止 float。
5. 统一返回：`{"code":0,"msg":"ok","data":...}`，业务异常不走 HTTP 500 兜底。
6. 涉及单据状态变更必须记录操作人、操作时间、单据号。
7. 不允许删除原文档定义的表字段，只能追加并说明用途。
8. 并发场景：出库/盘点对 `inventory` 行使用 `SELECT ... FOR UPDATE`，事务内完成「校验 → 扣减 → 写流水 → 提交」。

## 3. 时间规范

- 所有时间字段统一 `DATETIME`，使用**服务器本地时间**，不存 UTC，不做时区转换。
- 每张表带 `created_at DATETIME`，需要更新追踪的表带 `updated_at DATETIME`。

## 5. 统一响应规范

```json
{
  "code": 0,
  "msg": "ok",
  "data": {},
  "trace_id": "可选"
}
```

**错误码分段**：
- `0` 成功
- `400xx` 参数错误
- `401xx` 未登录 / 无权限
- `409xx` 业务冲突（库存不足、入库数量超限、状态不对）
- `500xx` 系统异常

## 6. 鉴权规范

- Header：`Authorization: Bearer <token>`
- 用户 ID 从 token 解析，**不允许前端传 uid 覆盖**。
- JWT 过期时间：`[待确认]`（建议 2 小时）
- 是否有 refresh_token：`[待确认]`（默认无，过期重新登录）

## 7. 模块开发顺序

1. 基础档案：商品、分类、单位、供应商、客户、仓库
2. 采购：订单 → 入库 → 库存增加 → 流水
3. 销售：订单 → 出库 → 库存扣减 → 流水
4. 库存查询、盘点、流水追溯
5. 权限登录
6. 报表放最后
