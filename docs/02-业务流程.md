# 业务流程

> 每个流程包含：涉及表 → 前置校验 → 事务步骤 → 锁与并发 → 异常分支 → 验收标准。  
> 库存字段统一为 `inventory.quantity`。所有库存变更必须写 `inventory_logs`。

---

## 一、采购入库确认

### 涉及表
`purchase_orders`、`purchase_order_items`、`purchase_ins`、`purchase_in_items`、`inventory`、`inventory_logs`

### 前置校验
1. `purchase_ins.status = 0`（草稿），否则返回状态错误。
2. 入库明细 `quantity > 0`。
3. 本次入库数量 ≤ 订单未入库数量（`purchase_order_items.quantity - received_qty`）。
4. 商品、仓库有效且未删除。

### 事务步骤（同一事务内）
1. **锁 `purchase_ins` 行**：`SELECT ... FOR UPDATE`，确认状态为 0。
2. **锁 `inventory` 行**：按明细 `product_id` **升序**逐个 `SELECT ... FOR UPDATE`（防死锁）；不存在则插入 `quantity=0` 后再加锁。
3. 更新 `purchase_ins.status = 1`，写 `operator_id`、`in_date`。
4. 逐条更新 `purchase_order_items.received_qty += 本次入库数量`。
5. 逐条 `inventory.quantity += 入库数量`，记录 `before_qty` / `after_qty`。
6. 逐条写 `inventory_logs`：`direction='in'`，`biz_type='purchase_in'`，`biz_no=in_no`。
7. 判断采购订单状态：
   - 所有明细 `received_qty >= quantity` → `purchase_orders.status = 2`（已完成）
   - 部分入库 → `status = 1`（部分入库）
8. 提交事务；任何步骤异常 → **整体回滚**，不残留流水与库存变更。

### 锁与并发
- 锁顺序固定：`purchase_ins` → `inventory`（按 product_id 升序）。
- 多并发同时确认不同入库单但涉及同一商品时，因 `inventory` 行锁串行化，不会重复加库存。

### 异常分支
| 场景 | 错误码 | 处理 |
|------|--------|------|
| 入库数量 > 订单未入库数量 | 40901 | 回滚，提示具体商品超限 |
| 入库单状态 ≠ 0 | 40902 | 回滚，提示单据状态错误 |
| 商品不存在/已删除 | 40001 | 回滚 |
| 数据库异常 | 50001 | 回滚，记录日志 |

### 幂等
- 同一 `purchase_ins.id` 重复提交：若 `status=1` 直接返回成功（状态幂等），不重复加库存。

### 验收标准
- [ ] 入库后 `inventory.quantity` 增加量 = 入库数量。
- [ ] `inventory_logs` 的 `before_qty` = 入库前库存，`after_qty` = before + 入库数量，连续无跳变。
- [ ] `purchase_order_items.received_qty` 累加正确。
- [ ] 订单状态自动流转（部分/完成）。
- [ ] 重复提交确认接口不产生双倍入库。
- [ ] 异常时库存与流水不残留。

## 二、销售出库确认

### 涉及表
`sales_orders`、`sales_order_items`、`sales_outs`、`sales_out_items`、`inventory`、`inventory_logs`

### 前置校验
1. `sales_outs.status = 0`（草稿）。
2. 出库明细 `quantity > 0`。
3. 本次出库数量 ≤ 订单未出库数量（`sales_order_items.quantity - shipped_qty`）。
4. **库存充足校验**：`inventory.quantity >= 出库数量`。  
   > **负库存策略**：`[待确认]` 默认不允许负库存。若允许，移除本校验。

### 事务步骤（同一事务内）
1. **锁 `sales_outs` 行**：`SELECT ... FOR UPDATE`，确认状态为 0。
2. **锁 `inventory` 行**：按明细 `product_id` **升序** `SELECT ... FOR UPDATE`。
3. 再次校验库存（行锁后读到最新值）：不足则回滚返回 40903。
4. 更新 `sales_outs.status = 1`，写 `operator_id`、`out_date`。
5. 逐条更新 `sales_order_items.shipped_qty += 本次出库数量`。
6. 逐条 `inventory.quantity -= 出库数量`，记录 `before_qty` / `after_qty`。
7. 逐条写 `inventory_logs`：`direction='out'`，`biz_type='sale_out'`，`biz_no=out_no`。
8. 判断销售订单状态：全部出库 → 2，部分 → 1。
9. 提交；异常整体回滚。

### 锁与并发
- 锁顺序固定：`sales_outs` → `inventory`（按 product_id 升序）。
- 库存校验在**行锁之后**执行，防止并发超卖。

### 异常分支
| 场景 | 错误码 | 处理 |
|------|--------|------|
| 库存不足 | 40903 | 回滚，提示具体商品库存不足 |
| 出库数量 > 订单未出库数量 | 40904 | 回滚 |
| 出库单状态 ≠ 0 | 40905 | 回滚 |
| 商品不存在 | 40001 | 回滚 |

### 幂等
- 同一 `sales_outs.id` 重复提交：若 `status=1` 直接返回成功。

### 验收标准
- [ ] 出库后 `inventory.quantity` 减少量 = 出库数量。
- [ ] 流水 `before_qty` / `after_qty` 连续。
- [ ] 库存不足时不扣减、不写流水、返回 40903。
- [ ] 并发两个出库单抢同一商品最后一件库存，只有一个成功。
- [ ] 订单状态自动流转。

## 三、库存盘点

### 涉及表
`inventory`、`inventory_logs`  
> 盘点单表 `[待确认]`：本期是否需要独立的 `stock_checks` / `stock_check_items` 表？以下流程假设**直接调整库存**，不建盘点单表。

### 前置校验
1. 商品、仓库有效。
2. 实盘数量 ≥ 0。

### 事务步骤（同一事务内）
1. **锁 `inventory` 行**：`SELECT ... FOR UPDATE`。
2. 计算差异：`diff = 实盘数量 - 当前 quantity`。
3. 若 `diff = 0`，不写流水，直接返回。
4. 更新 `inventory.quantity = 实盘数量`，记录 `before_qty` / `after_qty`。
5. 写 `inventory_logs`：`direction='adjust'`，`biz_type='check_adjust'`，`biz_no` 为盘点单号（自动生成或传参）。
6. 提交；异常回滚。

### 锁与并发
- 单商品盘点只锁 `inventory` 行。
- 多商品盘点按 `product_id` 升序加锁。

### 异常分支
| 场景 | 错误码 | 处理 |
|------|--------|------|
| 实盘数量 < 0 | 40002 | 回滚 |
| 商品库存记录不存在 | 40003 | 回滚（或自动创建，[待确认]） |

### 验收标准
- [ ] 盘点后 `inventory.quantity` = 实盘数量。
- [ ] 有差异时流水 `change_qty` = diff，`before_qty`/`after_qty` 正确。
- [ ] 无差异时不写流水。

## 四、采购订单创建（简要）

### 涉及表
`purchase_orders`、`purchase_order_items`

### 步骤
1. 校验供应商、仓库、商品有效。
2. 写 `purchase_orders`（status=0 待入库）。
3. 批量写 `purchase_order_items`，`received_qty=0`，`amount=quantity×price`。
4. `total_amount = Σ amount`。
5. 不影响库存。

---

## 五、销售订单创建（简要）

### 涉及表
`sales_orders`、`sales_order_items`

### 步骤
1. 校验客户、仓库、商品有效。
2. **库存充足提示**：查询各商品库存，不足则返回警告（`[待确认]` 是阻断还是仅提示；默认仅提示，不阻断建单）。
3. 写 `sales_orders`（status=0 待出库）。
4. 批量写 `sales_order_items`，`shipped_qty=0`。
5. 不扣减库存（本期不做库存占用）。
