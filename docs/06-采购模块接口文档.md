> 本模块路由前缀为 `/api/v1/purchases`，在 `main.py` 中挂载，所有端点需登录鉴权。
> 统一响应结构见 `00-SDD总览.md` 第 5 节。

## 一、基本信息

- **服务地址**：`http://localhost:8002`
- **前缀**：`/api/v1/purchases`
- **认证**：Header `Authorization: Bearer <JWT>`，用户 ID 从 token 解析，不允许前端传 uid 覆盖。
- **统一响应**：
  ```json
  {
    "code": 0,
    "msg": "ok",
    "data": {}
  }
  ```
- **业务码分段**：

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40001 | 参数校验失败（必填缺失、格式错误、超收、对象不存在） |
| 40101 | 未授权 / Token 无效 |
| 40401 | 资源不存在 |
| 40901 | 状态冲突（状态机不允许、重复操作） |

## 二、采购订单接口

### 1. 创建采购订单

- **路径**：`POST /api/v1/purchases/orders`
- **request**：
  ```json
  {
    "supplier_id": 1,
    "warehouse_id": 1,
    "remark": "可选备注",
    "items": [
      {
        "product_id": 1,
        "quantity": "100.00",
        "unit_price": "12.50",
        "remark": "可选"
      }
    ]
  }
  ```
- **字段说明**：
  - `supplier_id` int 必填，供应商存在且未删除
  - `warehouse_id` int 必填，仓库存在且未删除
  - `items` 数组必填，至少 1 条；同一订单内 `product_id` 不可重复
  - `quantity` decimal(12,2)，必须 > 0
  - `unit_price` decimal(12,2)，必须 ≥ 0
  - **不传** `amount`、`total_quantity`、`total_amount`、`order_no`、`status`，全部服务端生成
- **response.data**（`PurchaseOrderResponse`）：含 `id`、`order_no`、`status=draft`、`total_quantity`、`total_amount`、`supplier_name`、`warehouse_name`、`items[]`（每条含 `amount`、`received_quantity=0`、`product_name`、`product_sku`）
- **校验规则**：供应商/仓库/商品存在性校验；商品不重复；金额服务端计算（`amount = quantity × unit_price`，头汇总）
- **错误码**：40001（缺参 / 商品不存在 / 商品重复）；40101

---

### 2. 采购订单列表

- **路径**：`GET /api/v1/purchases/orders`
- **query**：
  - `skip` int 默认 0
  - `limit` int 默认 100
  - `status` 可选，按订单状态筛选（draft / submitted / approved / partial_in / completed / cancelled）
  - `supplier_id` 可选，按供应商筛选
  - `keyword` 可选，按订单号或备注模糊匹配
- **response.data**：`PurchaseOrderResponse[]`（含明细，按 id 倒序）
- **错误码**：40101

---

### 3. 采购订单详情

- **路径**：`GET /api/v1/purchases/orders/{order_id}`
- **response.data**：`PurchaseOrderResponse`（含 `items[]` 全字段）
- **错误码**：40401 订单不存在；40101

---

### 4. 修改采购订单

- **路径**：`PUT /api/v1/purchases/orders/{order_id}`
- **request**：同创建（`PurchaseOrderUpdate`，字段与 `PurchaseOrderCreate` 一致）
- **前置条件**：订单状态必须为 `draft`，否则返回 40901
- **明细处理**：全量替换——删除旧明细，按入参重建；`received_quantity` 重置为 0
- **错误码**：40901 非草稿不可修改；40001 参数校验；40401；40101

---

### 5. 提交审核

- **路径**：`POST /api/v1/purchases/orders/{order_id}/submit`
- **前置条件**：`draft` → `submitted`
- **response.data**：更新后的 `PurchaseOrderResponse`
- **错误码**：40901 非草稿不可提交；40401；40101

---

### 6. 审核通过

- **路径**：`POST /api/v1/purchases/orders/{order_id}/approve`
- **前置条件**：`submitted` → `approved`，写入 `approved_by = 当前用户ID`
- **response.data**：更新后的 `PurchaseOrderResponse`
- **错误码**：40901 非待审核不可审核（含重复审核）；40401；40101

---

### 7. 取消订单

- **路径**：`POST /api/v1/purchases/orders/{order_id}/cancel`
- **前置条件**：任意非 `completed` 状态可取消 → `cancelled`；`completed` 不可取消
- **联动**：取消订单时，关联的 `draft` 状态入库单一并置为 `cancelled`
- **错误码**：40901 已完成不可取消 / 已取消不可重复取消；40401；40101

---

### 8. 删除采购订单

- **路径**：`DELETE /api/v1/purchases/orders/{order_id}`
- **前置条件**：仅 `draft` 可删（逻辑删除，`is_deleted=1`）
- **response.data**：`null`
- **错误码**：40901 非草稿不可删除；40401；40101

---

## 三、采购入库单接口

### 1. 基于订单创建入库单

- **路径**：`POST /api/v1/purchases/orders/{order_id}/ins`
- **request**：
  ```json
  {
    "items": [
      {
        "purchase_order_item_id": 1,
        "quantity": "60.00",
        "unit_price": "12.50",
        "batch_no": "BATCH-001",
        "remark": "可选"
      }
    ]
  }
  ```
- **字段说明**：
  - `purchase_order_item_id` 必填，必须属于该订单
  - `quantity` decimal(12,2)，> 0，且 ≤ 该订单明细未入库数量（`quantity - received_quantity`）
  - `unit_price` 可选，不传则取订单明细单价
  - `batch_no` 可选，批次号（会写入库存流水 remark）
  - 同一入库单内商品不可重复
- **前置条件**：订单状态为 `approved` 或 `partial_in`
- **response.data**：`PurchaseInResponse`（含 `items[]`，状态为 `draft`）
- **错误码**：40901 订单状态不可创建入库单；40001 明细不属于订单 / 超收 / 商品重复；40401；40101

---

### 2. 入库单列表

- **路径**：`GET /api/v1/purchases/ins`
- **query**：`skip`、`limit`、`status`（draft/confirmed/cancelled）、`purchase_order_id`
- **response.data**：`PurchaseInResponse[]`

---

### 3. 入库单详情

- **路径**：`GET /api/v1/purchases/ins/{in_id}`
- **response.data**：`PurchaseInResponse`（含 `items[]`、`order_no`、`supplier_name`、`warehouse_name`）

---

### 4. 确认入库（核心，联动库存）

- **路径**：`POST /api/v1/purchases/ins/{in_id}/confirm`
- **前置条件**：入库单状态为 `draft`
- **同一事务逻辑**（全部在一个 `db.commit()` 内完成，任一步失败整体回滚）：
  1. 校验入库单为 `draft`
  2. 逐条校验超收：`order_item.received_quantity + in_item.quantity ≤ order_item.quantity`
  3. 累加 `purchase_order_items.received_quantity += in_item.quantity`
  4. 入库单置 `status=confirmed`，`confirmed_by=操作人`，`confirmed_at=NOW()`
  5. 订单状态：全部明细 `received_quantity ≥ quantity` → `completed`，否则 → `partial_in`
  6. 调用 `crud.inventory.create_stock_movements` 批量入库（仅 `flush`，不 `commit`）
  7. `db.commit()` 一次提交
- **库存联动**：
  - `inventory_balances.current_quantity += quantity`（无则新建）
  - 写 `stock_movements`，每条：`movement_type='IN'`、`reference_type='PURCHASE'`、`reference_id=入库单id`、`remark=batch_no`
- **response.data**：确认后的 `PurchaseInResponse`
- **错误码**：40901 非草稿不可确认（含重复确认）；40001 超收；40401；40101

---

### 5. 取消入库单

- **路径**：`POST /api/v1/purchases/ins/{in_id}/cancel`
- **前置条件**：仅 `draft` 可取消 → `cancelled`；`confirmed` 不可取消
- **错误码**：40901 已确认不可取消 / 已取消不可重复取消；40401；40101

## 四、状态流转图

### 采购订单

```
draft ──submit──▶ submitted ──approve──▶ approved ──partial confirm──▶ partial_in ──all confirmed──▶ completed
  │                  │                       │                            │
  └──────────────────┴───────────────────────┴────────────────────────────┴──cancel──▶ cancelled

（completed 不可取消）
```

| 动作 | 前置状态 | 目标状态 |
|------|----------|----------|
| 创建 | — | draft |
| submit | draft | submitted |
| approve | submitted | approved |
| 部分入库确认 | approved / partial_in | partial_in |
| 全部入库确认 | partial_in | completed |
| cancel | 非 completed | cancelled |

### 采购入库单

```
draft ──confirm──▶ confirmed
  │
  └──cancel──▶ cancelled

（confirmed 不可取消）
```

| 动作 | 前置状态 | 目标状态 |
|------|----------|----------|
| 创建 | — | draft |
| confirm | draft | confirmed |
| cancel | draft | cancelled |

## 五、业务规则

1. **分批入库**：一张订单可创建多张入库单，逐张确认，`received_quantity` 累加。
2. **超收拦截**：创建入库单时校验 `quantity ≤ 未入库数量`；确认入库时再次校验 `received_quantity + 本次 ≤ quantity`，双重保障，任一环节超收返回 40001。
3. **收齐转态**：所有明细 `received_quantity ≥ quantity` 时，订单自动转 `completed`；否则转 `partial_in`。
4. **金额服务端计算**：明细 `amount = quantity × unit_price`；头 `total_quantity` / `total_amount` 由明细汇总，前端不传。
5. **单据号**：
   - 订单号：`PO-YYYYMMDD-序号`（4 位补零，如 `PO-20261018-0001`）
   - 入库单号：`PI-YYYYMMDD-序号`
   - 取当天最大序号 +1，唯一约束兜底，冲突重试一次。
6. **库存联动**：确认入库写 `inventory_balances`（增加余额）与 `stock_movements`：
   - `movement_type = 'IN'`
   - `reference_type = 'PURCHASE'`
   - `reference_id = 入库单 ID`
   - `remark = batch_no`
7. **事务一致性**：`confirm_in` 全部操作在同一事务内，`create_stock_movements` 只 `flush` 不 `commit`，由采购模块统一提交；任一步失败整体回滚。
8. **取消联动**：取消订单时，关联的 `draft` 入库单一并置为 `cancelled`；`confirmed` 入库单不受影响。

## 八、前端对接注意事项

1. **创建订单不传金额**：`amount`、`total_quantity`、`total_amount` 均由服务端计算，传了也会被忽略（Create Schema 不含这些字段）。
2. **修改订单明细全量替换**：`PUT /orders/{id}` 传入的 `items` 会整体替换原明细，不是增量；修改后 `received_quantity` 重置为 0。
3. **入库用 `purchase_order_item_id`，不是 `product_id`**：创建入库单时必须传订单明细 ID，前端从订单详情 `items[].id` 取。
4. **分批入库**：一张订单可多次创建入库单，只要累计不超过订购数量即可；每张单独确认。
5. **超收提示**：创建入库单时若数量超过剩余未入库数量会直接返回 40001，前端可据此提示。
6. **查库存流水**：调用 `GET /api/v1/inventory/movements`，按 `reference_type=PURCHASE` + `reference_id=入库单id` 过滤，可追溯该入库单的库存变动。
7. **状态只读**：订单和入库单的 `status` 不通过修改接口变更，只能通过 submit / approve / cancel / confirm 专用动作接口变更。
8. **取消联动**：取消订单会连带取消其下 draft 状态的入库单，前端需刷新入库单列表。
