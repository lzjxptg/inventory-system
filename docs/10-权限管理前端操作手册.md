# 权限管理前端操作手册

版本：v1.0
日期：2026-10-20
适用模块：RBAC 权限管理

## 1. 概述

系统采用 RBAC（基于角色的访问控制）模型，通过「角色 → 权限」关联控制用户可访问的菜单、页面与按钮。
预置两个角色：

- **admin**（超级管理员）：拥有全部权限，可见「系统设置」菜单。
- **operator**（普通操作员）：可查看与创建数据，无删除与配置权限。

## 2. 角色管理页

**入口**：左侧菜单「系统设置 → 角色管理」（仅 admin 可见）。

### 2.1 新增角色

1. 点击右上角「新建角色」按钮。
2. 在弹窗中填写：
   - **角色编码**（必填）：唯一标识，如 `finance`、`warehouse_keeper`。
   - **描述**（选填）：角色用途说明。
3. 点击「保存」。若编码已存在，系统提示错误。

### 2.2 编辑角色

1. 在角色列表行点击「编辑」。
2. 修改角色编码或描述后保存。
3. 修改编码时同样校验唯一性。

### 2.3 删除角色

1. 点击行内「删除」。
2. 确认弹窗后角色被逻辑删除（`is_deleted=1`），列表中不再显示。
3. 已绑定该角色的用户 `role_id` 仍指向该角色，但角色不可用。

### 2.4 分配权限（权限树勾选）

1. 点击行内「分配权限」按钮，打开权限分配弹窗。
2. 权限树按**模块**分组（settings / purchase / sales / inventory / reports）。
3. 勾选需要的权限（支持父子联动，半选状态自动识别）。
4. 点击「保存权限」——系统**全量覆盖**该角色的权限（旧关联先删后插）。
5. 权限编码示例：`purchase:view`、`purchase:create`、`purchase:delete`、`role:manage`、`user:role`。

## 3. 用户角色分配页

**入口**：左侧菜单「系统设置 → 用户角色」（仅 admin 可见）。

1. 页面展示全部用户列表，含「当前角色」标签列。
2. 在操作列下拉框中选择目标角色。
3. 选择后立即提交，提示「已将 xxx 的角色更新」。
4. 用户重新登录后新角色生效（JWT 中的 role 字段在登录时写入）。

## 4. 菜单与按钮权限说明

### 4.1 菜单级权限

- 「系统设置」菜单（角色管理、用户角色）仅 `admin` 可见。
- 其他业务菜单（库存、采购、销售、报表）admin 与 operator 均可见。
- 实现：`Layout.vue` 中 `v-if="authStore.hasRole(['admin'])"` 控制。

### 4.2 路由级权限

- 路由 `meta.roles` 配置允许的角色列表。
- `router.beforeEach` 守卫：当前用户角色不在白名单时，重定向到 `/dashboard` 并提示「无权限访问该页面」。
- 受保护路由：`/settings/roles`、`/settings/user-role`（仅 admin）。

### 4.3 按钮级权限

- 通过自定义指令 `v-permission="'权限编码'"` 控制按钮显隐。
- 用法：
  ```html
  <el-button v-permission="'role:manage'">新建角色</el-button>
  <el-button v-permission="['purchase:delete', 'sales:delete']">删除</el-button>
  ```
- 若当前用户无对应权限，按钮在 DOM 挂载时被移除。
- 前端仅隐藏入口，**后端接口仍强制校验**，防止绕过 UI 直接调用。

## 5. admin 与 operator 权限差异对照

| 功能 | admin | operator |
| --- | --- | --- |
| 查看仪表盘/库存/采购/销售/报表 | ✅ | ✅ |
| 新建采购单 / 销售单 | ✅ | ✅ |
| 入库 / 出库操作 | ✅ | ✅ |
| 删除采购单 / 销售单 | ✅ | ❌ |
| 角色管理（新增/编辑/删除角色） | ✅ | ❌ |

## 6. 常见问题

- **Q：修改角色权限后立即生效吗？**
  A：后端权限实时生效（每次请求查库）。前端按钮显隐在下次拉取 `/roles/me/permissions` 时更新（刷新页面或重新登录）。

- **Q：operator 直接在地址栏输入 /settings/roles 会怎样？**
  A：被路由守卫拦截，重定向回 `/dashboard` 并提示无权限。

- **Q：用户未分配角色（role_id 为 NULL）怎么办？**
  A：默认按 `operator` 角色处理。
