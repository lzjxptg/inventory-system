## 一、基本信息

- **服务地址**：`http://localhost:8002`
- **前缀**：`/api/v1/sales`
- **认证**：Header `Authorization: Bearer <JWT>`，用户 ID 从 token 解析，不允许前端传 uid 覆盖。
- **统一响应**：
  ```json
  {
    "code": 0,
    "msg": "ok",
    "data": {}
  }
  ```
- **业务码分段**：

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40001 | 参数校验失败（必填缺失、格式错误、超发、超卖、对象不存在） |
| 40101 | 未授权 / Token 无效 |
| 40401 | 资源不存在 |
| 40901 | 状态冲突（状态机不允许、重复操作） |

## 二、销售订单接口

### 1. 创建销售订单

- **路径**：`POST /api/v1/sales/orders`
- **request**：
  ```json
  {
    "customer_id": 1,
    "warehouse_id": 1,
    "remark": "可选备注",
    "items": [
      {
        "product_id": 1,
        "quantity": "100.00",
        "unit_price": "12.50",
        "remark": "可选"
      }
    ]
  }
  ```
- **字段说明**：
  - `customer_id` int 必填，客户存在且未删除
  - `warehouse_id` int 必填，仓库存在且未删除
  - `items` 数组必填，至少 1 条；同一订单内 `product_id` 不可重复
  - `quantity` decimal(12,2)，必须 > 0
  - `unit_price` decimal(12,2)，必须 ≥ 0
  - **不传** `amount`、`total_quantity`、`total_amount`、`order_no`、`status`，全部服务端生成
- **response.data**（`SalesOrderResponse`）：含 `id`、`order_no`、`status=draft`、`total_quantity`、`total_amount`、`customer_name`、`warehouse_name`、`items[]`（每条含 `amount`、`shipped_quantity=0`、`product_name`、`product_sku`）
- **校验规则**：客户/仓库/商品存在性校验；商品不重复；金额服务端计算（`amount = quantity × unit_price`，头汇总）
- **错误码**：422（空明细 min_length=1）；40001（缺参 / 商品不存在 / 商品重复）；40101

---

### 2. 销售订单列表

- **路径**：`GET /api/v1/sales/orders`
- **query**：
  - `skip` int 默认 0
  - `limit` int 默认 100
  - `status` 可选，按订单状态筛选（draft / submitted / approved / partial_out / completed / cancelled）
  - `customer_id` 可选，按客户筛选
  - `keyword` 可选，按订单号或备注模糊匹配
- **response.data**：`SalesOrderResponse[]`（含明细，按 id 倒序）
- **错误码**：40101

---

### 3. 销售订单详情

- **路径**：`GET /api/v1/sales/orders/{order_id}`
- **response.data**：`SalesOrderResponse`（含 `items[]` 全字段）
- **错误码**：40401 订单不存在；40101

---

### 4. 修改销售订单

- **路径**：`PUT /api/v1/sales/orders/{order_id}`
- **request**：同创建（`SalesOrderUpdate`，字段与 `SalesOrderCreate` 一致）
- **前置条件**：订单状态必须为 `draft`，否则返回 40901
- **明细处理**：全量替换——删除旧明细，按入参重建；`shipped_quantity` 重置为 0
- **错误码**：40901 非草稿不可修改；40001 参数校验；40401；40101

---

### 5. 删除销售订单

- **路径**：`DELETE /api/v1/sales/orders/{order_id}`
- **前置条件**：仅 `draft` 可删（逻辑删除，`is_deleted=1`）
- **response.data**：`null`
- **错误码**：40901 非草稿不可删除；40401；40101

---

### 6. 提交审核

- **路径**：`POST /api/v1/sales/orders/{order_id}/submit`
- **前置条件**：`draft` → `submitted`
- **response.data**：更新后的 `SalesOrderResponse`
- **错误码**：40901 非草稿不可提交；40401；40101

---

### 7. 审核通过

- **路径**：`POST /api/v1/sales/orders/{order_id}/approve`
- **前置条件**：`submitted` → `approved`，写入 `approved_by = 当前用户ID`
- **response.data**：更新后的 `SalesOrderResponse`
- **错误码**：40901 非待审核不可审核（含重复审核）；40401；40101

---

### 8. 取消订单

- **路径**：`POST /api/v1/sales/orders/{order_id}/cancel`
- **前置条件**：任意非 `completed` 状态可取消 → `cancelled`；`completed` 不可取消
- **额外限制**：已出库（存在 `confirmed` 状态出库单）的订单不允许取消
- **联动**：取消订单时，关联的 `draft` 状态出库单一并置为 `cancelled`
- **错误码**：40901 已完成不可取消 / 已取消不可重复取消 / 已出库不可取消；40401；40101

## 三、销售出库单接口

### 1. 基于订单创建出库单

- **路径**：`POST /api/v1/sales/orders/{order_id}/outs`
- **request**：
  ```json
  {
    "items": [
      {
        "sales_order_item_id": 1,
        "quantity": "60.00",
        "unit_price": "12.50",
        "batch_no": "BATCH-001",
        "remark": "可选"
      }
    ]
  }
  ```
- **字段说明**：
  - `sales_order_item_id` 必填，必须属于该订单
  - `quantity` decimal(12,2)，> 0，且 ≤ 该订单明细未出库数量（`quantity - shipped_quantity`）
  - `unit_price` 可选，不传则取订单明细单价
  - `batch_no` 可选，批次号（会写入库存流水 remark）
  - 同一出库单内商品不可重复
- **前置条件**：订单状态为 `approved` 或 `partial_out`
- **response.data**：`SalesOutResponse`（含 `items[]`，状态为 `draft`）
- **错误码**：40901 订单状态不可创建出库单；40001 明细不属于订单 / 超发 / 商品重复；40401；40101

---

### 2. 出库单列表

- **路径**：`GET /api/v1/sales/outs`
- **query**：`skip`、`limit`、`status`（draft/confirmed/cancelled）、`sales_order_id`
- **response.data**：`SalesOutResponse[]`

---

### 3. 出库单详情

- **路径**：`GET /api/v1/sales/outs/{out_id}`
- **response.data**：`SalesOutResponse`（含 `items[]`、`order_no`、`customer_name`、`warehouse_name`）

---

### 4. 确认出库（核心，联动库存）

- **路径**：`POST /api/v1/sales/outs/{out_id}/confirm`
- **前置条件**：出库单状态为 `draft`
- **同一事务逻辑**（全部在一个 `db.commit()` 内完成，任一步失败 `db.rollback()` 整体回滚）：
  1. 校验出库单为 `draft`
  2. 逐条校验超发：`order_item.shipped_quantity + out_item.quantity ≤ order_item.quantity`
  3. 累加 `sales_order_items.shipped_quantity += out_item.quantity`
  4. 出库单置 `status=confirmed`，`confirmed_by=操作人`，`confirmed_at=NOW()`
  5. 订单状态：全部明细 `shipped_quantity ≥ quantity` → `completed`，否则 → `partial_out`
  6. 调用 `crud.inventory.create_stock_movements` 批量出库（仅 `flush`，不 `commit`）
  7. `db.commit()` 一次提交；异常时 `db.rollback()` 后重新抛出
- **库存联动**：
  - `inventory_balances.current_quantity -= quantity`（余额不足由库存模块拦截）
  - 写 `stock_movements`，每条：`movement_type='OUT'`、`reference_type='SALE'`、`reference_id=出库单id`、`remark=batch_no`
- **超卖拦截**：由 `create_stock_movements` 内部对负 `quantity` 校验库存充足，不足抛 `ValidationException(40001)`，触发回滚
- **response.data**：确认后的 `SalesOutResponse`
- **错误码**：40901 非草稿不可确认（含重复确认）；40001 超发 / 库存不足；40401；40101

---

### 5. 取消出库单

- **路径**：`POST /api/v1/sales/outs/{out_id}/cancel`
- **前置条件**：仅 `draft` 可取消 → `cancelled`；`confirmed` 不可取消
- **错误码**：40901 已确认不可取消 / 已取消不可重复取消；40401；40101

## 四、状态流转图

### 销售订单

```
draft ──submit──▶ submitted ──approve──▶ approved ──部分出库──▶ partial_out ──全部出库──▶ completed
  │                  │                       │                            │
  └──────────────────┴───────────────────────┴────────────────────────────┴──cancel──▶ cancelled

（completed 不可取消；已出库（有 confirmed 出库单）的订单不可取消）
```

| 动作 | 前置状态 | 目标状态 |
|------|----------|----------|
| 创建 | — | draft |
| submit | draft | submitted |
| approve | submitted | approved |
| 部分出库确认 | approved / partial_out | partial_out |
| 全部出库确认 | partial_out | completed |
| cancel | 非 completed 且无 confirmed 出库单 | cancelled |

### 销售出库单

```
draft ──confirm──▶ confirmed
  │
  └──cancel──▶ cancelled

（confirmed 不可取消）
```

| 动作 | 前置状态 | 目标状态 |
|------|----------|----------|
| 创建 | — | draft |
| confirm | draft | confirmed |
| cancel | draft | cancelled |

## 五、业务规则

1. **分批出库**：一张订单可创建多张出库单，逐张确认，`shipped_quantity` 累加。
2. **超发拦截（双重校验）**：
   - 创建出库单时校验 `quantity ≤ 未出库数量`（`quantity - shipped_quantity`）
   - 确认出库时再次校验 `shipped_quantity + 本次 ≤ quantity`
   - 任一环节超发返回 40001
3. **超卖拦截**：确认出库时调用 `create_stock_movements`，对负 `quantity` 校验 `inventory_balances.current_quantity ≥ abs(quantity)`，不足返回 40001 并回滚。
4. **收齐转态**：所有明细 `shipped_quantity ≥ quantity` 时，订单自动转 `completed`；否则转 `partial_out`。
5. **金额服务端计算**：明细 `amount = quantity × unit_price`；头 `total_quantity` / `total_amount` 由明细汇总，前端不传。
6. **单据号**：
   - 订单号：`SO-YYYYMMDD-序号`（4 位补零，如 `SO-20261018-0001`）
   - 出库单号：`SOUT-YYYYMMDD-序号`
   - 取当天最大序号 +1，唯一约束兜底，冲突重试一次。
7. **库存联动**：确认出库写 `inventory_balances`（扣减余额）与 `stock_movements`：
   - `movement_type = 'OUT'`
   - `reference_type = 'SALE'`
   - `reference_id = 出库单 ID`
   - `remark = batch_no`
8. **事务一致性**：`confirm_out` 全部操作在同一事务内，`create_stock_movements` 只 `flush` 不 `commit`，由销售模块统一提交；`create_stock_movements` 与 `db.commit()` 包在 try/except 中，任一步失败 `db.rollback()` 整体回滚。
9. **取消联动**：取消订单时，关联的 `draft` 入库单一并置为 `cancelled`；`confirmed` 出库单不受影响；已出库订单不可取消。

## 八、前端对接注意事项

1. **创建订单不传金额**：`amount`、`total_quantity`、`total_amount` 均由服务端计算，传了也会被忽略（Create Schema 不含这些字段）。
2. **修改订单明细全量替换**：`PUT /orders/{id}` 传入的 `items` 会整体替换原明细，不是增量；修改后 `shipped_quantity` 重置为 0。
3. **出库用 `sales_order_item_id`，不是 `product_id`**：创建出库单时必须传订单明细 ID，前端从订单详情 `items[].id` 取。
4. **分批出库**：一张订单可多次创建出库单，只要累计不超过订购数量即可；每张单独确认。
5. **超发提示**：创建出库单时若数量超过剩余未出库数量会直接返回 40001，前端可据此提示。
6. **出库前确保库存充足**：确认出库时若库存不足返回 40001，前端应提示并引导先补货。
7. **查库存流水**：调用 `GET /api/v1/inventory/movements`，按 `reference_type=SALE` + `reference_id=出库单id` 过滤，可追溯该出库单的库存变动。
8. **状态只读**：订单和出库单的 `status` 不通过修改接口变更，只能通过 submit / approve / cancel / confirm 专用动作接口变更。
9. **取消联动**：取消订单会连带取消其下 draft 状态的出库单，前端需刷新出库单列表。
